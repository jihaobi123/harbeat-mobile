# Private music bridge

Extends the existing reservation workspace bearer, under `/listen/set-api/music`.
Never forwards an end user's bearer to upstream services; fixed loopback search calls send only the existing origin and import marker. Add `music-routes.nginx.conf`, update this directory's systemd unit and pinned dependencies, then restart **only** `harbeat-activity-sets`. The long-running `harbeat-listen-imports` service must remain running. `listen_imports.store` is loaded from its existing deployment through `PYTHONPATH`; it neither imports `server` nor starts another GPU worker or calls `Jobs.recover`.

- `GET search?scope=library|discover&q=...&provider=all|netease|qq`: library preserves `{query,mode,coverage,message}` and joins `results` against the currently published index, adding title/BPM/status labels and verified artwork. Discover retains provider status and links, returns private `discoveryId` for each metadata-only result. External rows are never playable.
- `POST matches {discoveryId}`: `{candidates:[{candidateId,source,id,title,artist,duration,expected_duration?}],notes}`. Private candidates expire after 24 hours. User confirms the actual version before downloading; arbitrary URLs are not accepted.
- `POST download {candidateId,style?}`: one owned job. Empty style uses automatic analysis; nonempty style must be one of `GET jobs.styles`.
- `GET jobs`: `{jobs,styles}`. Jobs expose `{id,status,title,message,trackId,created,updated,coverUrl?}`. The ID belongs to this workspace and does not expose another user's queue entry. Exact existing worker states: `queued`, `downloading`, `transferring`, `analyzing`, `publishing`, `ready`, `ready_playback`, `failed`; bridge outbox initially uses `submitting`. `ready_playback` is single-song playback only.
- `POST jobs/{id}/retry`: only an owned failed job; retains the actual source identity. New submissions and retries share an 8-per-rolling-24-hour quota; at most 2 active requests per workspace. Existing queue's global limit 16 and storage guard 5 GiB still apply.
- `POST playlist {url}`: platform parser's first 24 metadata rows as `{title,results,message}`. The current legacy parser does not preserve platform track IDs; these rows use a private metadata-only candidate, then the existing title/artist source matcher. No synthetic platform ID is invented. Each version still requires confirmation.
- `POST upload` multipart `audio`, `title?`, `style?`: authenticate before multipart parsing. Audio max 100 MiB (request overhead capped at 64 KiB), supported audio suffix and actual ffprobe duration 20–1200 s. SHA dedup; extract embedded artwork before the existing worker can delete the original.
- `GET covers`: `{covers:{trackId:{url,masterSha256}}}` only for currently published identity. Artwork is fetched only from a checked official HTTPS CDN with public DNS; the connection pins the checked address, every redirect is rechecked, byte/pixel caps apply, images are reencoded to JPEG. Optional failure does not prevent music readiness. Source-input SHA must match import inventory and current detail's master SHA before association.

Durable outbox rows are committed before `Jobs.submit`. An acknowledgement lost during submission is recovered with the same provider/source ID or upload SHA, so the shared worker receives one logical job. A separate lightweight monitor checkpoints statuses and optional artwork independently of the slower reservation preparation thread. Closing the browser or stopping this bridge does not stop the pre-existing import worker.

Keep `music-covers/` traversable/readable by Nginx. `pending-covers/`, SQLite ownership tables and uploaded source paths stay private. The only new public image route accepts a 64-hex JPEG filename. Do not expose the import root, candidate rows, private job payload, or original NAS paths through Nginx.
