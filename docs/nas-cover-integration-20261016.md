# NAS 封面接入准备

## 当前状态

2026-10-16 用户正在上传 NAS 封面。已准备前端展示组件；当前读取的 `/api/analysis-lab/reports` 列表与抽查详情没有封面字段，因此尚未声称接通真实封面，也没有更新手机 APK 或发布新版本。上传完成后需要确认实际字段、图片读取地址以及歌曲身份关联，再接入仓库层并进行网页、Android 验收。

## 展示方式

- 音乐首页：真实封面放在原有挂环纸质卡片内，标题、艺人、BPM、收藏和播放入口保持原布局。
- 收藏陈列：封面显示在唱片封套上，露出的黑胶使用相同图片作为中心标签。歌单陈列使用歌单中首个有封面的曲目作为代表，不将歌单虚构成专辑。
- 展开列表：右侧歌曲卡片显示各自封面；左侧黑胶中心显示当前选择歌曲的封面，随播放旋转，暂停停止。手机上的唱片位置略向右移动，保证中心图片可见。
- 播放页与迷你播放器：使用同一歌曲的封面。刷新后的封面从当前曲库对象读取，不更换正在播放的音频对象。

`Track.coverUrl` 为可选字段，`withCoverUrl` 只替换展示信息，保留已验证的原曲、分析版本及时间轴。仓库层的真实字段映射暂未实施，避免猜测上传后的接口格式。下一步尤其需要将最新封面与六首固定分析版本分别处理，防止旧的精选报告遮盖新封面。

`TrackArtwork` 只加载 HTTP(S) 图片，无图片、加载中或图片失败时保留原图形；换歌后不会沿用上一首的图片。图片解码宽度随组件尺寸限制在 64–1024 像素，并复用 Flutter 图片内存缓存。中心图片和播放动效仍遵守系统减少动态效果偏好。

## 已验证

- `flutter analyze --no-pub` 无问题。
- `flutter test --no-pub --concurrency=1`：104 项通过。
- 新增测试以受控图片响应验证成功加载、404 后回退、换歌封面同步、黑胶播放旋转以及封面更新不替换音频；这些结果不代表 NAS 图片在线验证。
- 原有 360/390/430 宽度、1.5 倍文字、收藏展开、歌单管理和实时播放测试继续通过。

## 上传后的工作

确认真实封面字段及其与 `catalog_track_id` 的绑定，检查公开图片读取、格式、更新版本与网页跨域条件；接入摘要和详情并确保固定精选报告也能更新封面。用真实曲目检查首页、收藏、展开与播放页面，完成 APK 构建和真机安装验证后再更新交付版本与本说明。
