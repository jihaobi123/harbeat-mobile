# Jetson 判断、端侧执行的声部叠放方案

状态：用户已确认并要求继续执行。线上基线为 0.2.1+16，按迁移、独立试听、再决定上线的顺序实施。

## 分工

Jetson 分析音乐、检查声部素材，生成带来源证明的可执行编排。NAS 保存音源、分轨、分析和编排。云端管理预约任务、同步结果并分发素材。手机缓存、解码、保调变速，按同一音频时钟执行编排，并响应现场操作。

手机依据播放位置、用户风格／能量方向、缓存和设备状态，选择 Jetson 已批准的候选。手机继续检查文件身份、时间范围、授权接点和设备预算；音乐适配判断由 Jetson 提前完成。

## 现状核对

| 部分 | 当前实现 | 需要补充 |
| --- | --- | --- |
| 单曲分析 | Jetson 导出四分轨、125 ms 活动与音高摘要、鼓瞬态、连续小节证据 | 加入声部适用区间、资料覆盖检查和编排所需的尾音／空隙证据 |
| 曲对判断 | 手机计算实际窗口的声部重叠、FFT 音高差、人声退出和手法排序 | 移到 Jetson，输出结论、原因及允许的控制曲线 |
| 预约选点 | 云端运行现有 TS planner，手机按现场位置重新选点 | 在 Jetson 复用同一套选点代码，提前批准多个具体接点和后备方案 |
| 现场执行 | 手机运行 SoundTouch、Web Audio 增益／EQ／滤波和同钟接管 | 扩展为提前进入、稳定叠放、声部交接、B 接管的分阶段调度 |

Jetson 已有 Node v22.16.0，可运行打包后的现有 TS 选点代码。无需用 Python 重写一套不同的拍点、人声规则。

## 两种补法

推荐让 Jetson 输出完整的分阶段编排：每个接点包含声部、时间、曲线、退出条件和备选。手机可以在多个批准方案之间选择。它需要新增协议和调度测试，但能明确规定现场调整的范围。

较小的补法是 Jetson 只给固定模板签发适用资格，手机套用模板。它适合做第一个样例，但固定模板难以表达不同长度的人声拖尾、鼓段和旋律退出。首轮可用一个固定模板验证，协议仍按完整编排设计。

## Jetson 生成什么

每个编排包记录：

- A/B 曲目、原曲／分轨／报告／特征指纹、分析运行 ID、算法和策略版本。
- 具体的 A 时间与 B 源时间映射、允许的变速率，以及拍点和完整小节检查结果。
- 多个未来授权接点，每个接点有独立 ID；手机只能选仍在未来、素材覆盖完整的接点。
- 每阶段参与的声部及其增益、EQ、滤波曲线，以及阶段之间连续的控制值。
- 人声保留到何时、B 人声何时可进入、允许退出的后续边界。
- 所需素材清单、候选收益、风险、拒绝原因和批准状态。
- 已批准的原渐混后备，以及可以缩短或取消扩展叠放的具体边界。

数据分为单曲可复用证据和按接点评估的曲对编排。先计算预约 set 和实际试听需要的曲对，按双方来源、窗口、速率、曲线和策略版本缓存，避免全库穷举。候选不足时如实显示覆盖缺口。

评估必须覆盖整个提前进入、保持和交接过程，使用实际控制曲线。现有按线性渐混计算的声部重叠指标，不能直接充当稳定叠放的适用结论。

Jetson 需要检查：

1. 整段拍点误差、节拍漂移、完整小节和变速范围。
2. 实际同时可闻的贝斯与旋律区间、局部音高关系、节奏密度和瞬态重叠。
3. A 人声活动及尾音、B 人声可进入的空隙；短换气不能作为唱完。保持现有来源绑定的人声规则。
4. 各声部采样对齐、前后素材覆盖、分离残留风险和混合能量／峰值余量。

125 ms 活动不是语义歌词句尾，音高摘要不是和弦真值，多频段鼓瞬态也不是底鼓／军鼓分类。缺失资料保持未知；新叠放手法经试听后才批准用于自动选择。

## 先完成判断迁移

先让 Jetson 影子计算现有六种手法的结论，与现手机路径做同曲对、同接点对照。这个阶段保持现有曲线。

复用 `joint-stretch.ts`、`source-features.ts` 的纯计算部分，统一源片段、采样率、时间映射和测量定义。Jetson 的现有摘要比较与手机窗口 FFT 定义不同，迁移时不能直接替换并宣称等价。出现选择差异时记录原因并复核。

通过后，手机消费 Jetson 输出的手法资格、曲线和后备；停止在播放期间重新分析音高差、人声句尾或声部适配。下载校验、解码、保调变速和音频限幅仍属于端侧执行。

旧版预约保持兼容并提供显式升级入口。升级保留原 set 的可用曲目、实际数量和初始曲，来源变化使旧批准结果失效。新协议不能把旧包或未知指标当成已批准编排。

## 第一轮只增加 B 鼓声部提前叠放

沿用既有受益曲对，准备 6 组对照。每组比较原渐混、已验证的最佳单项、最佳单项加 B 自然鼓声部提前叠放。主交接点、B 正文进入位置、BPM、其他声部曲线、EQ 和人声规则固定。

首轮控制如下，属于待试听的实验参数：

| 阶段 | 行为 |
| --- | --- |
| 提前进入，1 小节 | A 正常继续，B 只加入自然鼓声部，增益从 0 到该声部原增益的 0.25 |
| 稳定叠放，2 小节 | B 鼓保持 0.25，A 保持原播放；B 人声、贝斯和旋律在新增前奏阶段均不引入 |
| 原主交接窗口 | 其他声部沿用已验证方案；B 鼓增益连续衔接为 `max(0.25, 原 B 渐混增益)`，避免在交接开始处先掉回零 |
| B 正文接管 | A 在原批准退出边界结束，B 接续原批准正文位置 |

新增的是 B 鼓提前进入的时间与曲线，不提前移动原主交接点。B 使用进入窗口之前的连续自然鼓段，不循环或重排。B 前置素材不足、节拍不稳、鼓组重叠风险高或能量余量不足时跳过该曲对，不移动其他接点凑样例。

三版采用同一源时间映射、总线设置和共同的安全余量，参照版关闭新增鼓层，避免把制备方式变化混入编排对比。迁移阶段先独立核对现有制备差异。

首轮含前奏的完整窗口不超过 24 秒，并保留现有 32 秒硬上限及 96 MiB 混音窗口、32 MiB 变速源预算。素材一段一段解码，长窗口按实际预算减少同时预热数，不能为保持数量突破内存限额。此轮不扩到 8／16 小节长叠放。

去人声的伴奏叠放、独立贝斯更长的交换、旋律保持等组合，在本轮记录适用、无改善与失败情况后逐项比较。使用四声部时，贝斯静音与低频 EQ 分开表达；移走贝斯并不会移走鼓轨里的底鼓。

## 手机允许怎样实时调整

手机持续准备附近的批准候选，自动和手动共用结果。

- 自动播放按预约方向选择批准的最佳候选；手动下一首选择仍有执行提前量的附近批准接点。
- 调整风格或能量时，切换到对应批准候选并取消尚未提交的旧准备。
- 素材不足时，使用同接点已批准的原渐混后备；所有后备都无法就绪时继续当前曲目，等待下一个批准接点。
- 扩展叠放只可在 Jetson 明列的后续边界缩短，声部增益只在包内允许范围调整；阶段切换不能突然跳变。
- 暂停冻结音频时钟，继续恢复同一时间线；停止取消计划。交接进入提交区后，新方向请求在该交接完成后处理。
- 音量保护和音频／网络状态监测在端侧执行，记录实际选择、曲线、后备原因及接管结果。

Jetson 临时不可用时，本机已保存且来源仍匹配的批准结果继续可用。未批准的新曲对等待补算，手机不临时编造高级声部方案。

## 验收与交付顺序

1. 验证判断迁移：相同输入和参数下核对指标、资格、控制曲线及拒绝原因，单独复核定义不同造成的差异。
2. 验证协议与执行：拒绝来源变更、越界曲线、过期接点、素材缺口和超预算；覆盖暂停、取消、改方向、网络晚到和正文接管。
3. 生成 6 组真实音乐盲听，播放器允许随时选择，不强制听完整段。
4. 收集每组偏好及失拍、鼓太密、人声残留、能量突变、空洞、退出突兀等现象。
5. 试听结论允许哪些组合后，再接入预约和自动主链路。网页验证与 Android 实机性能分别记录。

先完成分工迁移和这一种短叠放试听，后续手法沿用“单独验证后再组合”的顺序。
