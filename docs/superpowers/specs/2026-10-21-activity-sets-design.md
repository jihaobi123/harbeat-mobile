# 我的预约与可复用 set

用户已确认上一轮的预约方案，并要求在新界面执行：我的预约、详情进入播放、结束后保存 set、下次复用。同时恢复和扩充 Hip-Hop 候选。音乐补充作为独立运维任务记录，不改变混音算法。

## 界面与数据

在“我的”增加“我的预约”，列表展示名称、风格、活动时间、服务端准备进度及本机素材状态。创建表单含名称、多风格、开始时间、预计时长和能量。默认今天稍后、一小时，用户可改；不代替用户自动建立真实活动。

预约和素材包分开：预约记录保存开始/结束时间，set 包保存候选曲目、固定接点、既有六项规则结果和音频身份。结束时间只改变活动标签，不删除包。再次预约创建新时间记录，引用原包，已有素材不重复渲染。旧包版本继续保留，源报告改变时明确需要更新。

未登录的当前 NAS 模式也可使用。服务端创建随机私有工作区，凭据存设备安全存储，普通本地状态只存摘要。所有预约元数据接口都验证工作区凭据并限制记录数量；不同设备首次使用不会默认为同一用户。提供预约备份导出/导入以迁移同一私有工作区，不公开分享凭据。今后可另接账号同步，本次不伪称已经账号同步。

## 服务端准备

独立 `activity_sets` 服务部署在云端 loopback，SQLite 保存预约、包、进度及任务检查点。进程恢复后继续未完成任务；任务由服务端拥有，页面关闭不影响。按开始时间优先准备，立即检查现有分析，只选已发布且通过混音条件的歌曲，不重跑合格分析。

使用当前 TypeScript `rankChoices` / `rankNearbyChoices` 与上游正式 planner 的打包 CLI 产生有界候选和接点，不在 Python 重新发明选点阈值。首版每包最多 12 首候选、每首最多两个准备点/目标，避免全曲库所有曲对组合。候选不够、某速度区间无出口、部分任务失败分别显示；不以活动时长承诺足够多不重复歌曲。

逐个调用既有 metric gateway，沿用原 worker 的验证、评分和声音处理。复制或硬链接已选择方案及原版到独立内容寻址目录，保留真实结果指纹。包不依赖普通 smart-media 的临时清理；原曲分段和报告指纹也记录在包中。磁盘不足保持可追溯失败，不删除旧 set 释放空间。

## 播放与手机准备

点击预约详情的进入播放按钮，将 set 候选范围和已准备结果交给现有 metric 引擎，正常跳转主播放页。播放前仍检查来源、速度、拍点、正文和时间，不将过期结果硬安排。自动接歌优先使用本包已准备且通过当前检查的点；Next 维持正式就近选择，同点已有结果可以直接使用，没有时保留现有回退。

提供“准备本机素材”，下载验证该 set 所需原曲分段、选中转场和正文到现有本机缓存，报告当前实际可用数量。网页首次依赖用户打开页面完成这一下载，不假设关闭页面后持续运行。云端 ready 与本机 ready 分开。设备缓存被清理后可从保留的 set 重新下载。

## 验证边界

测试持久化、工作区隔离、取消/重启、复用不重渲染、过期不删除包、错误来源/媒体路径拒绝、候选池限制及准备结果复用。Flutter 测试表单、列表、详情和进入播放；实际浏览器创建测试预约、观察真实任务、打开播放及重载保留。用户尚未指定真实活动时间，测试活动明确标识。保留现在的非预约播放功能。
