## 手机音频实现

- `NativeMixAudio` 使用固定版本 `flutter_soloud 4.1.7` 的 C++ 混音器。A/B 两路共用音频时钟，预加载结束后读取实时位置，再将起播时间和线性淡化提交到原生引擎；Dart 的 80 ms 轮询只更新状态、结束清理和恢复速度，不逐帧执行音量淡化。
- 接入用户 vocal-v4 的合并人声区间、前后 400 ms 留白、进点评分、直接/倍速/半速 BPM 兼容规则。Dart 进点计算与原始 Python v4 生成的 24 组样例一致。手动命令采用未来 8 小节内的实时出点约束，与离线 90–205 秒分段策略有明确区别。
- 后端旧版 `vocal_events.start/end` 按秒转毫秒。缺失报告不等同无人声；节拍待复核不用于对齐。缺少可靠节拍或 BPM 不兼容时使用短原速淡化。
- 音频解码器支持的 MP3/WAV/FLAC/OGG 可混音；解码失败时单曲播放可退到原系统播放器，AAC/M4A 不承诺参与本版混音。下载最多 200 MB，使用请求头鉴权、禁止重定向，缓存位于 App 私有临时目录。
- 暂停、定位、取消、耳机拔出、音频焦点中断均取消待执行切换。音频引擎确认完成后才提交方向与当前歌曲；预加载失败继续当前音频。
- 手动“下一首 / 混入”沿用队列，不转成风格自动选曲；混音完成前不移动队列位置，重复下一首不会覆盖待执行请求，取消后重试仍指向同一首。只有一首时明确提示先添加歌曲。
- Android 通知栏/后台控制由 `audio_service` 对接。iOS 使用同一 Dart/C++ 执行层，已补蓝牙说明和原有后台音频配置，但尚未通过 Mac/Xcode 构建或 iPhone 实测。

这不是整个离线算法包的等价移植：尚未接入 v4 全集合 beam 排序、完整离线出点规划、资产 manifest/SHA 绑定验证或分轨 DSP。16 小节连续恢复在原脚本中也只作为计划字段；本版在重叠结束后恢复原速，恢复状态由轮询推进。专业音乐素材的听感、长时间热耗和不同蓝牙音频路由仍需专项验收。

## 安卓原生音频测量

设备为 130ddcca / Xiaomi MIX 4 / Android 12。独立包 `com.example.harbeat.nativeqa` 使用自产 440 Hz 与 660 Hz WAV，测试下一路 1.05 倍速、两秒交叉淡化、暂停和取消。最终设备日志显示测试通过。

原生输出缓冲采集约 4.83 秒；重叠区间检测到两路声音。660 Hz 信号变速后的主峰约 662 Hz，恢复原速后回到 660 Hz；未校正的 1.05 倍速应为 693 Hz。因此这里是**近似保调**，并非零误差保调或专业听感验收。测试中对应 660 Hz 与 693 Hz 的幅度约 0.00576 与 0.000605。原生暂停位置保持，取消返回 false 且原曲继续。

最初 QA 采集将双声道误设为单声道，导致频谱断续；核查插件 C++ 采集实现后改为同采样率双声道采集并分离左声道。没有为了通过测试而修改混音输出或降低原来的幅度断言。

输出样本：`outputs/HarBeat-native-mix-QA-20260920.wav`，是混音器缓冲输出，不是手机扬声器的声学录音。证据在工作区 `debug-output/native-qa-device.log`、`native-qa-mix-stereo.f32`。

## BLE 实现与边界

使用 `flutter_reactive_ble 5.5.0`：Android 按系统版本申请附近设备/旧版定位权限，真实扫描 15 秒；用户选择设备后连接、发现 GATT 服务和可通知特征。iOS 由原生 CoreBluetooth 请求授权。断开、取消和过期回调通过代次标记隔离。

设备按键协议页只允许订阅当前设备提供的通知特征，并按用户提供的完整十六进制数据包映射三个快捷动作。未知、空、超长数据不执行动作，重复配置被拒绝，有 200 ms 防抖。没有猜测 UUID 或把旧 RK 键盘协议当成 BLE 协议。

仍需要实际饰品型号、服务 UUID、通知 UUID 和按键格式来验收硬件端到端动作。代码接入、协议解析测试或扫描成功均不等同已经验证真实饰品按键。

9 月 20 日在 MIX 4 上完成“连接附近的设备”系统授权，15 秒真实扫描返回附近设备名称与 RSSI。没有连接归属不明的设备，也没有把这些设备视为用户饰品。浏览器中同入口明确提示使用 Android/iOS App。
