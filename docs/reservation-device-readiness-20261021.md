# 预约与本机接歌准备

预约提前准备多个退出点、进入点和候选歌曲。用户点下一首时，仍等附近合适的拍点、人声句尾或段落边界；自动接歌与手动切歌使用同一批候选。

页面分开显示三种状态：

| 状态 | 含义 |
| --- | --- |
| 云端已备齐 | 预约的候选策略和所需素材已在服务器准备好，设备未必已经下载。 |
| 素材已下载 | 本设备下载并校验了清单中的编码音频。缓存可能被系统清理，这个状态不代表所有音频已经解码和完成变速。 |
| 附近接点已就绪 N 个 | 当前播放歌曲之后的 N 个候选，已经完成端侧准备。只显示当前仍可安排的接点。 |

进入预约播放后，设备按播放进度滚动准备近期候选，不同时解码整个 set。准备过程中，页面显示“正在准备附近接点”；已有候选可用时先显示就绪数量，并提示仍在准备后续接点。换歌或改变音乐方向后，过期候选不应继续显示为可用。

预约音频使用单独的编码缓存，最多 1 GiB、2048 个片段；设备剩余空间较少时，只使用剩余配额的 80%。它与普通播放的 256 MiB、256 文件缓存分开保存，普通播放淘汰临时文件时会保留预约副本。播放到某个片段时，校验预约副本并交给现有解码器，PCM 和实时混音缓冲仍保持各自的内存限制。

已保存的预约副本可直接解码，读取它不要求再次成功写入磁盘。支持 Web Locks 的浏览器会在同源页面之间串行修改预约缓存，写入前刷新共享文件索引；旧 WebView 回退为本页面内串行处理，最终存储仍受系统配额控制。

部分下载会显示实际已下载数量，写入配额不足、片段超限或最终校验缺失时显示部分完成。预约详情的“下载本机素材”用于减少网络等待；进入播放后的解码、保调变速和调度，仍由播放引擎完成。需要联网补读的素材也必须等准备完成，才能进入端侧就绪候选池。

旧预约仍保留原有播放入口，并标为“云端旧版已就绪”。点击“准备更多接点”后，云端会按新规则重新规划候选；仅打开预约详情不会覆盖旧准备结果。

本轮真实验收用 6 首曲目生成了 104 个候选；手动切歌命中预热的旋律滤波，自动接歌执行已准备的贝斯交接与旋律滤波，两次均在设备上完成。上线后新建的 4 首 Hip-Hop 预约完成了 72 个候选，失败数为 0，当前 ActivitySession 接受了完整清单与 282 个音频片段。详细记录见 [验收数据](reservation-prewarm-acceptance-20261021.json)。

新版通过 301 项 TypeScript、156 项 Flutter、57 项预约后端测试，以及 Android 素材验证。此次没有编译 APK，Android WebView、手机性能和蓝牙延迟仍需实机试听。
