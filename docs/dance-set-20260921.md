# 按风格与时长生成自动混音舞程

Android Preview 0.1.6+7。在现有播放页的 V3 模式增加“本次舞程”，保留原有颜色、播放卡与底部导航。选择音乐风格和约 5/10/15/20/30 分钟，点击自动选歌，查看歌曲后开始。支持重新选一组、取消准备等待、暂停和下一首；播放时自动衔接，按音频时钟计时并在目标时间附近淡出。

## 数据与选曲

- 2026-09-21 实际 NAS 目录 208 首，157 首满足本版来源、拍网格、人声绑定、局部能量、段落及进入窗口要求，51 首未进入自动舞程池。原推荐曲库保留全部目录曲目。
- 优先使用 NAS 目录风格标签；缺少标签时才使用已完成的风格模型结果。没有把 K-Pop 的模型 House 候选覆盖为人工 House 标签，也没有把 Baile Funk 合并到 Funk。
- Hip-Hop 20 首：可生成 5/10/15/20/30 分钟；House、Funk、Disco 各 5 首：当前支持 5 分钟；Electronic 13 首：支持至 15 分钟；K-Pop 82 首：支持至 30 分钟。另有 Afro、Amapiano、Dancehall、Baile Funk、Breakbeat 的 5 分钟选择。以服务当前返回为准。
- 后端用真实小节网格与 V3 的 0.8–1.2 变速边界检查相邻曲目，再按近似 BPM、可播正文容量选择不重复的歌曲；素材不足时拒绝对应时长，不用重复或其他风格凑数。
- 每首仍使用最多前 150 秒。舞程时长指这些歌曲片段实际连续播放的时间，不是歌曲原始时长相加。分配时间时考虑进入点之后剩余的正文，修复了晚进入歌曲导致平均分配提前播完的问题。

## 服务端

源码：`services/mobile_dance.py`。通过已有阿里云转发访问 Jetson Analysis Lab，添加以下派生资源 GET 接口；没有在手机内放入 SSH、管理员账号或中转令牌：

- `/api/analysis-lab/dance/catalog`：曲风、合格数量、可生成时长；初次索引准备时返回 loading，后续使用快照并后台刷新。
- `/api/analysis-lab/dance/set?style=Hip-Hop&minutes=5&variation=0`：读取/准备确定的选曲组合，返回任务或已准备结果。
- `/api/analysis-lab/dance/jobs/{id}`：准备进度与结果。
- `/api/analysis-lab/dance/assets/{sha256}.flac`：按内容哈希读取派生的单曲素材。

只写 NAS 下独立的 `data/analysis-platform/mobile-dance-v1` 派生缓存，原曲、生产数据库和分析报告不修改。单个素材准备工作线程、最多 3 个排队任务、每小时最多准备 12 组新组合；已存在组合直接复用。原有 HTTPS、中转令牌、同源校验和非 GET 管理员鉴权保持。

实际部署在 `/home/mark/harbeat-analysis-platform/analysis_platform/mobile_dance.py`，只在 server.py 加入路由安装入口。部署前核对 server.py 哈希、暂停补算调度并确认没有运行/排队分析任务，完成后恢复调度。原 server.py 备份在 `deploy-backups/20260921-mobile-dance/server.py`。独立 Lab 启动时扫描历史任务，实际产生过短暂 502，随后恢复；未重启生产 API。

## 手机执行

V3 原规划、DSP、AudioWorklet 字节不变，来源提交仍为 `279b65da50d436586c220fb38befdb03f6571099`。新增舞程调度层在手机上控制何时请求下一首，原规划器实时决定实际窗口并执行双轨 EQ、变速进入片段、淡化和限幅。没有生成整场预混音频。

Android 宿主只把指定 SHA 文件路径代理到固定 NAS 资源接口。音频先核对 SHA256，单文件上限 64 MB，下载缓存上限 600 MB；原 V3 PCM 缓存仍为 192 MB。准备与首次手机下载需要网络，首曲解码和候选预加载与播放器状态同步。

自动舞程内禁用单曲定位、上一首及任意候选选歌，避免破坏已经准备的相邻转场；使用下一首或停止重选。暂停或锁屏暂停共享音频时钟，不消耗舞程时间。iOS 和网页 Flutter 的本机 V3 宿主不在这次 Android 交付范围内。

- 真实进入片段下载的 SHA256/字节数符合准备清单；无效素材路径、任务编号、风格分别返回 404/422。
- 安卓包通过安全安装器更新，未卸载应用。具体安装哈希和版本见 `outputs/Dance-install-verification-20260921.json`。
- Hip-Hop 真机完整自动舞程：两次请求均为 `dance_auto`，分别在 109.215 秒与 197.462 秒完成切歌，299.857 秒完成整场。6 条音频处理块观察有非零峰值，最高约 0.864；无人工下一首操作。原始会话 `outputs/Dance-hiphop-phone-session-20260921.json`。

- 暂停验证：16:41:20 与 16:41:54 两份真机快照，舞程均为 3:22 / 5:00，单曲均为 1:19 / 2:30；继续播放后进度正常推进。暂停操作与系统后台事件在会话中分别记录，未把暂停等待计入跳舞时长。摘要见 `outputs/Dance-pause-verification-20260921.json`。

风格和小节仍是已有标签/分析结果，未声称完成人工听感校准。音频处理块峰值与时钟观察仅证明引擎执行，不是扬声器、耳机或蓝牙延迟测量。长于 5 分钟的舞程未做真机完整时长验收。
