# 新前端混音方案接入与准备耗时

本次只修改新前端引擎的调用和准备流程。已锁定的选点、动态 EQ、声音执行器及云端 `metric-mix-v1.0` 方法评分没有改变。上次恢复正式选材的检查继续生效。

## 当前实际接入的范围

| 候选 | 使用现有规则的条件 |
| --- | --- |
| 原渐混 | 缺少明确新增收益，或该接点的分轨方案未在预算内可播放 |
| 独立贝斯交接 | bass 分轨、同时可闻及局部音高分布依据通过检查 |
| 旋律残余滤波 | other 同时可闻达到门槛，只处理既有末小节 |
| 旋律让位 | other 重叠与音高分布差异达到较高门槛 |
| 人声唱完再退出 | 声学尾部、后续空隙、B 人声进入及保留收益通过检查 |
| 贝斯＋滤波 | 两个单项均合格，组合比分别较好单项还高出原规则要求的分差 |

这六项沿用既有 worker 判断，客户端不按曲名或风格重新决定效果。鼓循环、自然鼓桥、固定回声、伴奏短切、半倍速、大跨度、重触发、留白和第三首叠加仍属于此前各自的实验范围，没有全部进入这个自动选择器。既有试听结论不等于已经建立自动触发规则。

## 修复了什么

即时 Next／方向变化原先通常直接调用本地原渐混，云端分轨只有内存结果恰好同一接点时才能复用。现在同点已备好的内存结果仍直接使用；没有时，同时准备原渐混后备并有界检查云端同点方案。云端的推荐音频和 B 正文都装入才算可用。最多检查两秒，并在接点前留一秒安排时间；来不及则采用原定接点的原渐混，不为等效果改接点或改变 B 素材。

单次显式动作最多提交一个云端任务，跨接点重试和换候选共用这一次预算。接点太近、未发请求时不消耗这次机会。短预算内每 250ms 检查状态，自动准备仍使用原有 2 秒轮询。暂停、停止、换方向均取消等待和下载，晚回来的结果不能覆盖新请求；后端没有任务取消接口，已经提交的计算仍可能完成。

新增日志区分任务请求/确认、排队或执行状态、结果 ready、选中音频装入、可播放及回退原因。服务器返回 ready 不再被当作客户端下载完成。原渐混描述也改为“未在本次预算内可播放”，不再统一暗示带宽或数据缺失。

## 为什么有时来不及

单次真实 worker 复测使用 WHISTLE → REALLY REALLY、约 4.66 秒交接，结果如下：

| 阶段 | 耗时 |
| --- | ---: |
| 读取 NAS、核验原曲与分轨指纹 | 26.120 秒 |
| 读取片段、联合变速 | 4.640 秒 |
| 六版混音计算 | 1.265 秒 |
| worker 总耗时，含其他分析和写文件 | 32.664 秒 |
| 云端调用到 worker 返回，含通信及启动 | 35.351 秒 |

该任务六版输出共 8,235,160 字节。上述总耗时尚未包含完整结果 rsync 回云端及客户端下载；没有把它当作完整端到端耗时。源文件已经预处理，当前仍为每个新曲对/接点重新读取并核验源指纹、抽片段和渲染，这不是重新运行整曲分离模型。

本 Mac 公网读取一份 1,647,032 字节的既有 filter.wav：首字节约 0.155 秒，总计约 1.731 秒，约 0.952 MB/s。这是一次网络观测，不能推断购买带宽，也没有涵盖 NAS 到 Jetson 或 Jetson 到云端的全部链路。当前证据中，读取和核验 NAS 明显比这次客户端下载耗时更长，不能将“未就绪”都归为阿里云带宽不足。

保持分析与声音算法不变时，及时性依赖提前准备和缓存；若继续优化冷任务，应先单独评估可信源验证与片段缓存，不能为了速度直接省掉来源核验。

## 验证结果

新引擎 `metric-engine-BJKBhO7v.js` 的实际同源消息接口完成了两个真实 Next 案例。测试宿主先用已有 seek 接口定位再发送 Next，没有修改引擎内部状态或云端结果。

第一次冷元数据读取令源位置前进，正式选出 194.958 秒、B 的 w24-2。剩余检查预算约 162ms，准备阶段耗尽后采用原渐混，交接与正文接管两条观测均 late=0。

第二次同曲对元数据已经就绪，正式选出 192.758 秒、B 的 w16-2。云端在约 217ms 确认缓存，342ms 返回原有贝斯＋滤波决定，请求后约 349ms 所需音频可播放；随后同点采用 `bass_filter`，197.240 秒完成交接，B 从 62.33 秒继续正文。交接与正文接管两条观测均 late=0。这个案例有意验证已缓存结果复用，不代表冷任务可以即时生成，也不代替听感判断。

随后在用户的 Flutter 主页面重新加载同一引擎，点击实际“下一首”按钮完成 Replay → CALL ME BABY。所选 24.500–29.300 秒接点检查预算约 162ms，记录明确为 preparing/budget 回退，交接和正文接管均 late=0。主页面保留 KPOP、能量 3、自动接歌开启，结束时已暂停。

全部 TypeScript 测试 251 项通过、3 项跳过；类型检查、锁定上游来源校验和 Web 引擎构建通过。独立审查指出的短预算轮询和跨候选重复请求问题均用失败回归复现后修复。新逻辑已在本地 8766 页面使用，没有生成新 Android 包或部署新的云端 UI/worker。
