# 统一播放与自动接歌（2026-10-20）

## 用户看到的变化

主播放页只有一个播放器，不再要求在「标准播放」和「V3 实时混音」之间切换。点播放即播放原曲。不操作时，系统按原最佳接点自动衔接；点击右侧“下一首”或调整下面的能量、风格时，立即按当前方向寻找最近合格接点并安排混入。

- 「音乐方向」提供五档能量和真实在线目录的风格标签。「不限风格」会优先考虑节奏相容性；明确选风格后只在该标签内推荐，不偷偷扩大范围。
- 「接下来听」显示真实封面、下一首、推荐原因、预计接入时间、所选进入片段以及云端采用的处理方式。
- 自动接歌默认开启。无需点击「准备交接」或「确认接歌」；关闭后当前原曲继续播放。「下一首」是一次手动接歌，不会改变用户已关闭的自动开关。
- 正在播放时从音乐页选另一首，是指定下一首；暂停或停止时选歌则播放所选歌曲。不会同时开启两个音频播放器。
- 播放中改变风格或能量时，尚未提交的准备失效，改按新方向在最近合格点混入，当前歌不重播。在接点前最多十秒才提交音频调度，给用户保留重选的时间；已经提交的交接完整执行，新方向用于后续歌曲。
- 原纸质描边卡片、青绿/杏黄、封面、黑胶和过渡动效保留。新的推荐卡也使用黑胶封面和过渡动画，尊重系统减少动画设置。
- 「更多播放工具」内保留手动指定歌曲/方案、回放试听、导出记录，以及 Android 原连续播放策略和定时舞程。它们不占用主流程的模式选择。

缺少发布分析资料的音频继续通过原播放器播放；不把它伪装成可以做分轨混音。没有通过检查的下一首或接点时保留当前播放，显示原因，不硬切、不猜测缺失分析。手机目前未连接，本版只交付可安装 APK 和网络验证结果。

## 自动执行

1. 从 `/listen/library.json` 读取可播放且可混音的歌曲，按真实风格标签、速度和近期播放记录筛选，最多比较八首。元数据最多两路并发；一首资料失败不抹掉其他成功候选。
2. 读取源绑定的分析。复用上游择优器比较完整的 2/4/8 小节，优先最后 35% 实测音乐，必要时扩大到最后 50%。保留同一局部拍网格最大 65 ms 偏差门槛；云端当前支持的速率仍限 0.95–1.05。
3. 冷准备在当前播放位置后保留额外提前量，选择窗口时还应用上游的准备时间检查；提前获取转场和 B 接管后的正文片段，而非等到接点才请求云端。
4. 为排名最高的接点创建现有云端任务。云端重验来源、实测拍点和分轨，选择六种合格处理中的推荐项。手机校验结果、素材 SHA-256 和时长。
5. 准备就绪后显示下一首与倒计时；到接点前十秒内才调用同一个 AudioContext transport 调度 A→转场→B，B 从对应正文位置继续。250 ms 的界面/编排检查不承担实际音频定时。
6. B 接管后清除已经消费的选择，自动开始下一轮推荐，不把 B 推荐给自己。

云端或某个素材窗口失败时，只排除受影响接点并尝试本轮其他选择，单轮最多三个任务；失败重试有退避。接点过期必须重选，不能在错误位置补做已经过去的转场。暂停、停止、拖动、后台和偏好更改都会使旧请求失效；已调度的时间轴暂停与恢复由原 transport 处理。

## 五档能量的实际含义

使用来源绑定的原曲 `alignment.bandFrames.rmsDbfs`，比较 A 混入前四秒和 B 接管后四组四秒。统一数字功率只是选曲强弱的代理，不等于感知响度、舞蹈难度或音量旋钮。

- 五档的排序目标差值为 −2.5 / −1.25 / 0 / +1.25 / +2.5 dB。
- 低档要求 B 的四组接管窗口都比 A 低至少 1 dB；高档要求都高至少 1 dB。单组差值超过 6 dB 的候选不通过此方向检查。
- 在满足上游选点约束后，以四组窗口到目标差值的距离参与排序，保留上游的音量/低频、人声和段落评分。
- 不使用每首歌独立归一化的 `energy.value` 跨曲比较，也不把空缺测量当作零，不更改实际播放增益。
- 相邻档可能选到相同候选；没有符合方向的可靠接点时明确提示用户换方向。这不是承诺每一档都一定有可用音乐。

真实目录离线回归：Attention 作为 A、目标 Hip-Hop 时，档 1 选 HIPHOP 的较晚接点，档 2 选 Straight (Battle Beat)，档 3 选 Pandaaaaaa，档 4/5 选 HIPHOP 的另一个进入/退出组合。各档在该台电脑比较六首真实候选约需 100–135 ms；该时间不是手机性能承诺。

## 最近合格接点优先：原渐混兜底（2026-10-20）

主按钮现为“最近接点切歌”。用户明确选择：最近合格接点的分轨结果还没就绪时，先用原来的对拍渐混；同接点已有结果则照常使用。显式请求不再留出固定 40 秒，也不跳到自动续播的后段区域。
