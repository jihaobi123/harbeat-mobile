# 0.1.8+10 · 视觉更新与连续混音接入

## 视觉方向

依据用户提供的《HARBEAT UI 开发指南 · 问卷分析版》（2026-10-16）及三张参考图，以音乐播放器方案 A 为基础：浅色留白、青绿和杏黄、细描边与圆角。彩色文件夹参考用于歌单，硬边纸片层次只用于主播放卡和精选卡。参考图中的插画、艺人图片和商标没有复制为应用素材；唱片图形为 Flutter 原生装饰，不表示真实专辑封面或分析波形。

- `theme.dart` 统一背景 #F7F8F7、正文 #182224、次文字 #526467、深青 #006B73、青绿 #27B2BC、杏黄 #F7BC72；系统中文字体，页面标题 24、正文 16、辅助信息 14。
- 卡片圆角 16、输入框/按钮圆角 12、描边 1.5；普通按钮及图标按钮触控区至少 48。主播放按钮圆形 72，加载与播放共用固定图形空间。
- 播放页先显示歌曲、进度和传输控制，再显示连续混音/定时舞程的配置。暂停、循环、等待预算、下一首、停止、风格、时长、自动接歌、音量、日志入口全部保留。
- 音乐页保留推荐、搜索、曲库；收藏、歌单管理、详情、上传和本机导入继续使用原控制器。音乐选择页改为方案 A 的双列唱片封套：独立封面、细描边、偏移纸片背层、小挂环、收藏键和圆形播放键；上方提供分隔式搜索框。大字体自动单列。精选混音放在可展开的唱片合集里，保留原有三种播放入口。歌单采用方案 D 的双列文件夹：突出页签、露出的纸片、歌曲数量和独立编辑/删除键。
- 歌单遇到尚未加载的旧歌曲 ID 时显示可用数量，不再误报为空歌单；排序按实际歌曲 ID 映射，保留未加载条目。
- 主导航继续为播放、音乐、我的；不按参考原型删除现有账号和设备入口。跨页播放器保留上一首、播放/暂停和下一首。
- 账号、上传、设备与快捷控制页面共用新样式。选中项提供形状/勾选和语义状态，不只改变颜色。大字体允许增高换行；时间使用等宽数字。

## 与上次已发布版本的关系

本次也交付了 9 月 24 日已在工作区接入、尚未发布的连续混音适配，因此相对 0.1.6 的完整差异包含引擎更新。它不属于本次视觉设计新增的算法：

- 固定上游 `jihaobi123/harbeat-client` 的 `codex/continuous-live-20260924`，提交 `c81525d90b20e9b48d0bfc1dc8e3a8c12668c6bf`；各文件 SHA 见 `vendor/realtime-v3/upstream.json`。
- 手机适配调用连续选曲、按需准备和人声重叠/动态 EQ 方案；选下一首不重启当前歌曲，锁定交接期间的新选择排队，暂停/停止使未完成准备失效。
- 优先尝试上游完整曲库索引，不可用时明确标识 26 首已发布试听、每首最多 150 秒。没有把完整 157 首曲库视为已部署，也没有在 10 月 16 日重新同步 GitHub 算法。
- 原定时舞程与六首离线素材保留。混音需要应用在前台；锁屏或离开应用暂停。iOS 本地混音引擎仍未经 Mac/Xcode 真机验收。
- Android 网络桥接只允许指定素材路径，音频校验 SHA，限定大小与缓存预算；凭据不进入引擎资源。
- 修复 Android 打包时 `.json` 与 `.json.gz` 被资源合并器当作同名文件的问题。Android 仅打包 JSON，读取器在没有 gzip 文件时回退 JSON，APK 自身负责压缩。

## 构建与安装

```powershell
flutter pub get
python tools/build_realtime.py --download
flutter test --concurrency=1
flutter analyze
flutter build apk --release --target-platform android-arm64
powershell -File tools/install_preview.ps1 -Apk build/app/outputs/flutter-apk/app-release.apk -Serial <设备序列号>
```
