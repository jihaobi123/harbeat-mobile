# 网页即时接歌质量复核

这次生硬的主要可复现原因是即时接歌的选材发生了退化。新增的逐窗口“最早开始”排序绕过了原连续播放器先确定下一首进入素材、再比较接点的流程。此前只验证切换准时，没有充分检查选到哪段音乐；准时不能证明衔接好听。

现场导出的 6 次手动或方向切换全部采用本地原渐混，其中 5 次为 2 小节。2 小节本身不是错误，问题在于它可能只是因为时间戳早几毫秒而替代原本更合适的素材。

| 曲对 | 现场行为 | 相同播放位置的正式流程复算 |
| --- | --- | --- |
| Straight → Make It Right | 125.624 秒进入，2 小节、4.486 秒，B 从 63.62 秒进入 | 125.628 秒进入，4 小节、8.972 秒，B 从 45.50 秒进入；只晚约 4 毫秒 |
| MOP → Pandaaaaaa | 同时可闻人声代理约 0.117 | 同一个 A 开始点，换正式 B 素材后该代理为 0 |
| Make It Right → 아무노래 | 整个重叠段几乎都有双人声 | 原正式流程也无法充分避开；新增全段双人声检查，拒绝普通原渐混回退 |

本次恢复正式 `planContinuous` 的素材选择，固定 B 窗口、资产、速率和交接时长后，再比较未来合格 A 接点。冷下载和接点过期重试保留这个素材身份。先比较 18 秒范围内的候选，没有才扩到 60 秒；跨批次合并也按这个范围分层。拍点、速度、来源验证、EQ、正文覆盖和能量门槛继续生效。

现有同源节拍、音量和人声活动数据已经能够发现上述问题。本次没有重跑音乐分析。全段双人声门槛只拦截明显不适合普通渐混的情况；它不等于理解歌词，也不能保证较短的人声重叠合适。安全候选不足时继续当前歌曲。

## 声音实现比较

同曲对试听位于本地 `/handoff-quality/`。01 复现现场 2 小节素材，02 使用恢复后的 4 小节素材，03 用旧播放器的实际图、音源和调度方法渲染 02 的同一计划。三版公共增益均为 0.60，没有分别归一化，每版保留交接前后 4 秒。

对齐固定增益后，02 与 03 在重叠内部的相对数值误差约 −127.17 dB，最大绝对差 0.000001386。这个比较排除了前后各 30 毫秒、输出限幅器和实际设备，说明已测范围的原渐混实现没有明显差别；不代表整条播放链或主观听感完全一致。新播放器的固定播放增益较旧版低，试听已经统一这一差异。
